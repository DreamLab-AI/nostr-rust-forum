# External-review repairs — 2026-11-03

These producer changes implement the confirmed boundary repairs from the [source reconciliation](external-review-2026-11-02.md). They do not certify a deployed Worker or browser ceremony. Existing ADR decision and activation statuses remain unchanged.

| Concern | Repair and acceptance evidence |
| --- | --- |
| Passkey registration | Both clients now NIP-98-sign register/verify with the key derived in the ceremony. The auth Worker stores its random options salt against the registration challenge, retrieves only a matching unexpired registration challenge, and persists that exact salt with the credential. Caller-supplied replacements remain ignored. Credential insert and challenge/salt consumption share a D1 batch, with a conditional insert and changed-row check preventing a consumed challenge from succeeding again. A SQLite production-query fixture checks expiry/account binding and registration/login derivation equality. |
| Device registration | Both forum registration paths attach a short-lived owner-bound proof signed by the derived device key. Worker list serialisation emits integer JSON for integer database fields and rejects invalid numeric representations. Conditional upsert permits only active same-owner label updates; another owner or a revoked key returns 409. A fresh derived device key is required for re-enrolment. SQLite production-statement fixtures verify immutable owner, creation time and revocation; a wire fixture verifies integer fields. |
| Admin demotion | Auth gates, admin listing and moderation event validation no longer union auth members grants. Dynamic authority comes from the relay whitelist; admin listing bypasses the legacy KV cache. Pod administrative operations and payment cleanup also drop auth-member fallbacks; cleanup routes authority queries to RELAY_DB separately from payment data. A payment-route SQLite fixture verifies that relay demotion defeats a stale members grant. Explicit static bootstrap admins retain their independently configured authority. |
| Invites | Revoke accepts the unique id or code used by existing clients. Cohort grants union JSON sets in one SQLite UPDATE instead of SELECT/replace, preserving concurrent grants. A production-statement fixture verifies accumulated distinct grants. |
| Push | Drain claims the exact counter snapshot, token hash and bump sequence by conditional UPDATE, retries races up to eight times, then returns 503 for retry. The bump sequence prevents an emptied-and-refilled counter snapshot from being mistaken for the original. Delivery records the sequence captured before sending, so a later bump remains owed. Logout credentials are retained in page localStorage as well as service-worker IndexedDB. SQLite fixtures check competing drains, bump preservation and the captured-sequence wake condition. |
| Trust sweep | A capped/aborted sweep persists its last consumed stable sort key in relay D1. The next cron resumes after that key; completion clears it for the next full cycle. Schema/read/write failures are errors, never silent resets. The bounded-sweep fixture verifies progress past a permanently held prefix. |
| Information identity disclosure | Public rows now include registered=true for active agent_registry rows and registered=false for configured ingress-only disclosures. A durable row wins deduplication. Consumers must require the explicit bit when deciding whether provisioning is complete. Projection fixtures cover both cases. |
| Shared Solid contracts | The pod Worker now resolves every R2/KV policy read through Solid's classify_policy_read. Only confirmed absence ascends: unavailable, oversized or malformed child policy settles as denial without parent/KV fallback. Kit limits remain 64 KiB. The existing D1 replay adapter implements Solid ReplayStore directly; kit verification delegates to that implementation. SQL errors and unknown changed-row metadata produce ReplayError::Unavailable, while a duplicate nonce preserves its original expiry and returns Replayed. Production-statement SQLite fixtures cover these outcomes; shared classifier fixtures cover invalid-child denial and absent-child inheritance. |

Deployment must bind pod RELAY_DB to the instance's relay database; the kit template adds the binding with an explicit placeholder id. Auth schema reconciliation creates registration_salts. Existing credential salts are not rewritten: a credential registered by an older mismatched ceremony may require authenticated recovery/re-enrolment because its original PRF input cannot be reconstructed safely. No live identity was changed.

Validation receipts are reported in the estate integration report. Native Worker/SQL tests and WASM compilation exercise different boundaries; neither substitutes for real WebAuthn hardware, Cloudflare D1 or a deployed browser logout journey.
